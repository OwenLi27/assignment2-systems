# 数据并行的逐步优化：DDP → Sharded Optimizer → FSDP

> 对应讲义第 5–7 章。记录每一步优化解决了什么问题、每个 rank 持有和更新哪些东西，以及付出了什么代价。
>
> 相关笔记：[5.3.2 通信与计算重叠：同步 vs 异步](DDP的sync和async机制.md)

---

## 1. 先分清几个概念

| 概念 | 是什么 | 例子 |
|---|---|---|
| 模型参数 | forward / backward 里真正参与计算的权重 | `fc1.weight` |
| 梯度 | 每个模型参数各有一个，形状和参数相同 | `fc1.weight.grad` |
| 优化器状态 | 优化器为每个模型参数额外维护的辅助张量；不参与 forward，只在计算更新量时用 | AdamW 的 m、v、步数 t |
| 超参数 | 优化器的配置项，各 rank 都一样 | lr、betas、eps、weight_decay |

一次 optimizer step 会同时更新两样东西：一是用梯度和 m、v 去更新**模型参数**；二是更新 **m、v、t 本身**。

---

## 2. 逐步优化总览

| 方案 | 解决什么问题 | 带来的收益 | 代价 / 遗留问题 |
|---|---|---|---|
| **DDP naive** (5.2) | 用多张卡一起训练 | batch 被切开，每张卡只算 n/N 个样本，每步的计算量和激活值显存都分摊了 | 每个参数单独做一次同步 all-reduce，而且要等 backward 全部结束才开始；参数、梯度、优化器状态每张卡各存一整份 |
| **DDP flat** (5.3.1) | 通信调用次数太多 | 梯度拼成一个张量，只调用一次 all-reduce，省下每次调用的固定开销 | 多一块和全部梯度一样大的缓冲区，还要拷贝两次；通信仍然排在 backward 之后 |
| **DDP overlap** (5.3.2) | 通信时间全部暴露在外 | 在 hook 里异步发起 all-reduce，和 backward 同时进行，把通信藏到计算后面 | 调用次数和 naive 一样多；显存冗余完全没变 |
| **Sharded optimizer**（第 6 章） | 优化器状态冗余 | m、v 每张卡只存约 1/N；step 的计算也分摊开，不再每张卡重复做一遍 | 每步多一轮参数广播，还要等 step 最慢的那个 rank；参数和梯度仍然是全量 |
| **FSDP**（第 7 章） | 参数和梯度冗余 | 参数、梯度、优化器状态每张卡都只存约 1/N | 每层权重在 forward 和 backward 时各要 all-gather 一次，梯度要 reduce-scatter；需要预取才能把通信藏到计算后面；很小的层（比如 norm）不值得切分 |

一句话：DDP 的三个版本优化的是**速度**，即怎么分摊计算、怎么减少通信开销；sharded optimizer 和 FSDP 优化的是**显存**，即逐步去掉每张卡上的冗余。

## 3. 每个 rank 持有什么、更新什么

例子：4 个模型参数 P1–P4，2 个 rank。在 sharded optimizer 里，P1、P3 由 rank 0 负责，P2、P4 由 rank 1 负责。

### 3.1 DDP

按照batch切分训练数据

| | rank 0 | rank 1 |
|---|---|---|
| 持有的模型参数 | P1 P2 P3 P4（完整） | P1 P2 P3 P4（完整） |
| 持有的梯度 | 全部（all-reduce 之后已经是平均值） | 全部 |
| 持有的优化器状态 | P1–P4 的 m、v、t | P1–P4 的 m、v、t |
| step 时更新 | P1–P4，以及它们的 m、v、t | P1–P4，以及它们的 m、v、t（和 rank 0 的计算完全相同） |
| 别的 rank 更新的参数从哪来 | 不需要：用 all-reduce 之后的平均梯度，自己更新全部参数 | 同左 |

> DDP 的通信传的是**梯度**，不是参数。每个 rank 的本地梯度只来自自己那 1/N 的数据，各 rank 互不相同；all-reduce 把它们平均成全 batch 的梯度，step 时每个 rank 再用这份相同的梯度，各自更新全部参数。参数只在开始时广播一次，之后不再通信。
>
> 如果不做梯度 all-reduce，各 rank 会用各自的本地梯度更新参数，模型会越来越不一样，而且每个模型只从 1/N 的数据里学习，相当于 N 个各自独立的小 batch 训练。

### 3.2 Sharded optimizer

**建立在DDP之上**，数据照样切分、梯度照样做all-reduce，它只改了 step 这一步，从“每个 rank 更新全部参数”变成“只更新自己负责的那部分，再通过广播同步”。实际使用时，两者是一起用的。

sharded optimizer 的主要目的是省显存，不是加速。每个 rank 只为自己负责的参数保存 m、v，优化器状态的显存降到约 1/N。参数更新的计算也随之分摊了，但每一步要多做一轮广播，所以整体速度不一定更快。说它是“对优化器状态显存的优化”更准确。

| | rank 0 | rank 1 |
|---|---|---|
| 持有的模型参数 | P1 P2 P3 P4（完整） | P1 P2 P3 P4（完整） |
| 持有的梯度 | 全部（由 DDP 做 all-reduce，已经是平均值） | 全部（同左） |
| 持有的优化器状态 | **只有 P1、P3 的** m、v、t | **只有 P2、P4 的** m、v、t |
| step 时更新 | 用平均梯度**只更新 P1、P3**，以及它们的 m、v、t | 用平均梯度**只更新 P2、P4**，以及它们的 m、v、t |
| 别的 rank 更新的参数从哪来 | P2、P4 由 rank 1 广播过来 | P1、P3 由 rank 0 广播过来 |

切分的单位是**整个参数张量**：每个 rank 负责更新其中几个完整的张量，但所有张量的完整副本每个 rank 都保留着。

> 一步训练的完整顺序：forward / backward（每个 rank 用自己那份数据）→ DDP 对梯度做 all-reduce 求平均 → 每个 rank 用平均梯度只更新自己负责的参数 → 广播，让所有 rank 拿到全部更新后的参数。

### 3.3 FSDP

| | rank 0 | rank 1 |
|---|---|---|
| 持有的模型参数 | P1–P4 **每个张量的前一半** | P1–P4 **每个张量的后一半** |
| 持有的梯度 | 只有自己那几片的（通过 reduce-scatter 得到） | 只有自己那几片的 |
| 持有的优化器状态 | 只有自己那几片的 m、v、t | 只有自己那几片的 m、v、t |
| step 时更新 | 每个张量的前一半 | 每个张量的后一半 |
| 别的 rank 更新的参数从哪来 | step 之后不同步。下一次 forward 或 backward 用到某一层时，临时 all-gather 拼成完整权重，用完就释放 | 同左 |

切分的单位是**张量内部**：每个 rank 持有每个张量的一片，平时不保存任何完整的张量。

#### FSDP 用到的两个集合操作

两者都是集合操作（所有 rank 都要调用），作用正好相反：

- **all-gather**：每个 rank 各出一片（大小 S/N，内容各不相同），所有 rank 都得到按 rank 顺序拼好的完整张量（大小 S）。只收集、拼接，不做计算。
- **reduce-scatter**：每个 rank 各出一个完整张量（大小 S，值各不相同），先逐元素求和，再把结果切成 N 片，rank i 只拿到第 i 片（大小 S/N）。

例子（2 个 rank，在本机 Gloo 上实测）：

```text
reduce-scatter:
  rank 0 输入 [0, 1, 2, 3]      rank 1 输入 [10, 11, 12, 13]
  逐元素求和 = [10, 12, 14, 16]
  rank 0 得到 [10, 12]          rank 1 得到 [14, 16]

all-gather:
  rank 0 输入 [0, 0]            rank 1 输入 [1, 1]
  rank 0 得到 [0, 0, 1, 1]      rank 1 得到 [0, 0, 1, 1]
```

| 操作 | 在 FSDP 里用在哪 | 作用 |
|---|---|---|
| all-gather | 每层 forward、backward 计算之前 | 每个 rank 拿出自己那片权重，拼成完整权重供计算使用 |
| reduce-scatter | backward 算出某层梯度之后 | 每个 rank 用自己的数据算出完整梯度，求和后每个 rank 只拿自己那片，再除以 N 得到平均梯度 |

和其他集合操作对比：

| 操作 | 每个 rank 的输入 | 每个 rank 的输出 |
|---|---|---|
| broadcast | 只有 src 那个 rank 有数据 | 都得到 src 的数据 |
| all-reduce | 完整张量 | 所有 rank 求和后的完整张量 |
| reduce-scatter | 完整张量 | 求和结果中属于自己的那一片 |
| all-gather | 自己的一片 | 所有片拼起来的完整张量 |

- **all-reduce = reduce-scatter + all-gather**：讲义 §8.1 (p.40–41) 里的 ring all-reduce 就是这样实现的，两步各花 (N−1)/N · S/W 的时间。
- DDP 的每个 rank 都需要全部梯度，所以做完整的 all-reduce。FSDP 的每个 rank 只需要自己那片梯度，所以只做 reduce-scatter；原本 all-reduce 后半步的 all-gather，改放在下一次 forward 时用来拼权重。
- PyTorch 函数：`dist.reduce_scatter_tensor(输出, 输入)`、`dist.all_gather_into_tensor(输出, 输入)`。本机 torch 2.11 的 Gloo 都支持，也支持异步调用。

### 3.4 汇总

| 方案 | 模型参数 | 梯度 | 优化器状态 | 每个 rank 在 step 时更新什么 |
|---|---|---|---|---|
| DDP | 全量 | 全量 | 全量 | 全部参数（每个 rank 都重复算一遍） |
| Sharded optimizer | 全量 | 全量 | 约 1/N | 自己负责的那几个完整张量 |
| FSDP | 约 1/N | 约 1/N | 约 1/N | 每个张量中属于自己的那一片 |

## 4. 各 rank 的参数靠什么保持一致

| 方案 | 怎么保持一致 |
|---|---|
| DDP | 起点相同（开始时广播一次参数），之后每一步都用同一份平均梯度做同样的更新，**从此再也不传参数**。前提是 all-reduce 的结果在各 rank 上逐位相同，而且 all-reduce 之后的计算是确定性的 |
| Sharded optimizer | **每一步 step 之后**，由负责的 rank 把更新过的参数广播出去。广播是逐字节复制，所以广播后各 rank 的参数逐位相同 |
| FSDP | 不保存完整参数，每个 rank 只维护自己的那一片；需要完整权重时，临时 all-gather 拼出来 |

## 5. 每一步训练中的通信

| 方案 | 通信内容 | 什么时候发生 |
|---|---|---|
| DDP naive | 每个参数的梯度做一次同步 all-reduce | backward 结束之后 |
| DDP flat | 拼平后的梯度做一次 all-reduce | backward 结束之后 |
| DDP overlap | 每个参数的梯度做一次异步 all-reduce | backward 进行期间（在 hook 里发起） |
| Sharded optimizer | 梯度 all-reduce（由 DDP 负责），再加上每个参数一次 broadcast | backward 之后，以及 step 之后 |
| FSDP | 每层权重 all-gather（forward 和 backward 各一次）；每层梯度 reduce-scatter；不切分的参数 (norm) 的梯度做 all-reduce | 计算之前（预取），以及 backward 进行期间 |

注意：broadcast 也是集合操作，每个参数都要**所有 rank 一起调用**，只有 src 那个 rank 发送数据，其他 rank 接收。

## 6. 显存账（只算模型状态，FP32 + AdamW）

设参数个数为 Ψ，rank 数为 N。每个参数本身 4 字节，梯度 4 字节，m 和 v 合计 8 字节。

| 项目 | DDP | Sharded optimizer | FSDP |
|---|---|---|---|
| 模型参数 | 4Ψ | 4Ψ | 4Ψ / N，再加上正在计算的几层的临时完整权重 |
| 梯度 | 4Ψ | 4Ψ | 4Ψ / N |
| 优化器状态 | 8Ψ | 8Ψ / N | 8Ψ / N |
| 合计 | 16Ψ | 8Ψ + 8Ψ / N | 见下方说明 |

- N = 2 时，sharded optimizer 每张卡从 16Ψ 降到 12Ψ，省了 25%。N 越大，越接近 8Ψ，剩下的大头就是参数和梯度。
- 实测的峰值显存还包括激活值和各种临时张量。FSDP 相比第 6 章能省多少**峰值**显存，是 fsdp_accounting (a) 要回答的问题，留给自己推导。
- ZeRO 论文里的显存公式是按混合精度写的（K = 12）。和这里比较时，要先统一成同一种精度设定。

## 7. 每一步还剩下什么问题，下一步怎么解决

| 当前方案的问题 | 下一步 |
|---|---|
| DDP naive：通信调用次数多，而且通信和计算没有重叠 | flat 减少调用次数；overlap 把通信和 backward 重叠起来（两者结合起来就是分桶，PyTorch 自带的 DDP 就是这么做的） |
| DDP 的各个版本：模型状态在每张卡上都是全量冗余 | sharded optimizer 先切分其中最大的一项，优化器状态 |
| Sharded optimizer：参数和梯度仍然是全量，而且每步多一轮广播 | FSDP 把参数和梯度也切开 |
| FSDP：通信量更大，每层权重要 all-gather 两次 | 预取：第 i−2 层的 forward 完成后，就开始 gather 第 i 层，把通信藏到计算后面；很小的层不切分；有 `compute_dtype` 时先把权重转成低精度再通信，节省带宽 |
