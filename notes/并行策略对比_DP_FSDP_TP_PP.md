# 并行策略：DP、FSDP、TP、PP

训练时把工作分给多个 rank（每个 rank 通常是一张 GPU）。能切开的东西有三样：**数据**（样本）、**每一层的权重**、**层**。DP 和 FSDP 切数据，TP 切每一层的权重，PP 切层。

第一部分用一个很小的例子，把 DP、FSDP、TP 的每一步完整走一遍；第二部分对比它们，并扩展到 PP。

记号：`[1 2 3 4; 5 6 7 8]` 表示一个两行的矩阵，分号分隔各行；xᵀ 表示 x 的转置。

---

## 第一部分：用一个例子走完 DP、FSDP、TP

### 1.1 例子

```text
一个线性层：y = x · W

W = [1 2 3 4]      权重：2 个输入特征 → 4 个输出特征（2×4）
    [5 6 7 8]

两个样本：s1 = [1, 2]，s2 = [3, 4]（每个都是 1×2）
两个 rank：rank 0、rank 1
```

这一层位于网络中间：输入 x 来自前一层，输出 y 交给后一层。

**单机训练时的计算（作为标准答案）**

```text
forward：
  y1 = s1 · W = [11, 14, 17, 20]
  y2 = s2 · W = [23, 30, 37, 44]

backward：后一层传回每个样本输出的梯度 dy。为了好算，两个样本都取 dy = [1, 2, 3, 4]
  权重梯度：每个样本 G = xᵀ · dy，形状 2×4，和 W 相同
    G(s1) = [1; 2] · [1 2 3 4] = [1 2 3 4; 2 4 6 8]
    G(s2) = [3; 4] · [1 2 3 4] = [3 6 9 12; 4 8 12 16]
    batch 的 loss 是两个样本 loss 的平均，所以
    dW = (G(s1) + G(s2)) / 2 = [2 4 6 8; 3 6 9 12]
  输入梯度：每个样本 dx = dy · Wᵀ，形状 1×2，交给前一层继续反传
    dx1 = dx2 = [1 2 3 4] · Wᵀ = [30, 70]

update：用 dW 更新 W（如果用 Adam，还要更新优化器状态 m、v）
```

下面三种方案都用 2 个 rank 完成这些计算，最终的权重梯度必须和 dW 一致。

### 1.2 DP：切数据，每个 rank 存一整份权重

**分工**：rank 0 处理 s1，rank 1 处理 s2。两个 rank 各存一份完整的 W，以及完整的梯度和优化器状态。

**第 0 步：开始训练前，broadcast 权重。** 把 rank 0 的 W 复制给 rank 1，保证两份 W 完全相同。这一步只做一次。

**第 1 步：forward，不通信。**

```text
rank 0：y1 = s1 · W = [11, 14, 17, 20]
rank 1：y2 = s2 · W = [23, 30, 37, 44]
```

每个 rank 都有完整的 W 和自己的样本，计算所需的东西都在本地。

**第 2 步：backward，不通信。**

```text
rank 0：G0 = G(s1) = [1 2 3 4; 2 4 6 8]，dx1 = [30, 70]
rank 1：G1 = G(s2) = [3 6 9 12; 4 8 12 16]，dx2 = [30, 70]
```

dx1 只属于 s1，只有 rank 0 上的前一层需要它，所以也不用传。

**第 3 步：梯度同步，all-reduce。**

```text
all-reduce 求和：两个 rank 都得到 G0 + G1 = [4 8 12 16; 6 12 18 24]
各自除以 2：    两个 rank 都得到 dW = [2 4 6 8; 3 6 9 12]
```

为什么要同步：G0 只反映 s1，G1 只反映 s2，整个 batch 的梯度需要把两者合起来。all-reduce 之后，两个 rank 的梯度完全相同。

**第 4 步：update，不通信。** 两个 rank 用相同的 dW 做相同的更新，W 始终保持一致。所以权重只需要在开始时广播一次，之后不用再传。

**小结**：DP 把计算平分给两个 rank，每步只同步一次梯度。代价是每个 rank 都存完整的权重、梯度和优化器状态，N 个 rank 就有 N 份重复。

### 1.3 FSDP：切数据，也切权重的存储

**分工**：和 DP 一样，rank 0 处理 s1，rank 1 处理 s2。区别是平时每个 rank 只存 W 的一半，以及对应那一半的梯度和优化器状态：

```text
rank 0 存 W 的第 1–2 列：[1 2; 5 6]
rank 1 存 W 的第 3–4 列：[3 4; 7 8]
```

开始训练前同样要保证初始权重一致，比如先广播完整的 W，再由每个 rank 切出自己那一半。

**第 1 步：forward，先 all-gather 权重。**

```text
all-gather：rank 0 发出 [1 2; 5 6]，rank 1 发出 [3 4; 7 8]，两个 rank 都拼出完整的 W
rank 0：y1 = s1 · W = [11, 14, 17, 20]
rank 1：y2 = s2 · W = [23, 30, 37, 44]
算完立刻丢掉完整的 W，只留自己那一半
```

为什么要 gather：rank 0 要算出 s1 的全部 4 个输出特征（后一层需要完整的 y1），这要用到 W 的全部列。第 3–4 列在 rank 1 上，但 rank 1 没有 s1，帮不上忙，只能把权重搬到 rank 0。

**第 2 步：backward，再 all-gather 一次权重。**

```text
all-gather：两个 rank 再次拼出完整的 W（forward 之后已经丢掉了）
rank 0：G0 = G(s1) = [1 2 3 4; 2 4 6 8]，dx1 = [30, 70]
rank 1：G1 = G(s2) = [3 6 9 12; 4 8 12 16]，dx2 = [30, 70]
算完再丢掉完整的 W
```

- 需要完整 W 的是 dx：dx1 = dy · Wᵀ 要用到 W 的全部列。权重梯度 G = xᵀ · dy 只用到 x 和 dy，不需要 W。
- G0 的形状是完整的 2×4，但只包含 s1 的贡献，还不是整个 batch 的梯度。
- 和 DP 一样，dx1 留在 rank 0，不用传。

**第 3 步：梯度同步，reduce-scatter。**

```text
先逐元素求和：G0 + G1 = [4 8 12 16; 6 12 18 24]
再按列切开：  rank 0 拿第 1–2 列 [4 8; 6 12]，rank 1 拿第 3–4 列 [12 16; 18 24]
各自除以 2：  rank 0 得到 [2 4; 3 6]，rank 1 得到 [6 8; 9 12]
```

结果正好是 dW 的第 1–2 列和第 3–4 列。为什么不用 all-reduce：每个 rank 只负责更新自己那一半 W，只需要对应那一半的梯度。之后，完整形状的 G0、G1 也可以丢掉。

**第 4 步：update，不通信。** rank 0 用 `[2 4; 3 6]` 更新自己存的第 1–2 列，rank 1 用 `[6 8; 9 12]` 更新第 3–4 列。下一次 forward 会重新 all-gather，自然拿到更新后的权重。

**小结**：FSDP 中每个 rank 的计算和 DP 完全相同，区别只在存储：权重、梯度、优化器状态平时只存 1/N，用到某一层时才临时拼出完整的权重。代价是每层要多做两次权重 all-gather。

### 1.4 TP：不切数据，每个 rank 只用自己那片权重计算

**分工**：两个 rank 都处理 s1 和 s2。权重的存法和 FSDP 一样：rank 0 存第 1–2 列 W0 = `[1 2; 5 6]`，rank 1 存第 3–4 列 W1 = `[3 4; 7 8]`。但 TP 计算时每个 rank 只用自己那片，**从不拼回完整的 W**。

这里假设这一层的前一层和后一层都在每个 rank 上完整运行，也就是每个 rank 都需要完整的输入和输出。

**第 1 步：forward，算完再 all-gather 激活。**

```text
rank 0：[s1; s2] · W0 = [11 14; 23 30]  ← 两个样本的第 1–2 个输出特征
rank 1：[s1; s2] · W1 = [17 20; 37 44]  ← 两个样本的第 3–4 个输出特征
all-gather 激活：两个 rank 都得到 y1 = [11, 14, 17, 20]，y2 = [23, 30, 37, 44]
```

- 每个 rank 算出的就是最终值：y 的第 j 个特征只依赖 x 和 W 的第 j 列，所以 `[11, 14]` 就是 y1 前两个特征的最终结果，不需要再相加。
- 为什么要 all-gather：后一层需要每个样本的**全部 4 个特征**，而每个 rank 只算出了其中 2 个。
- 权重始终不动，搬的是激活。

**第 2 步：backward，权重梯度在本地算，输入梯度要 all-reduce。**

后一层在每个 rank 上都完整运行，所以两个 rank 拿到相同、完整的 dy：两个样本都是 `[1, 2, 3, 4]`。

权重梯度：rank 0 只负责 W0，只需要 dy 的第 1–2 个分量；rank 1 只需要第 3–4 个分量。

```text
rank 0：([1; 2] · [1 2] + [3; 4] · [1 2]) / 2 = ([1 2; 2 4] + [3 6; 4 8]) / 2 = [2 4; 3 6]
rank 1：([1; 2] · [3 4] + [3; 4] · [3 4]) / 2 = ([3 4; 6 8] + [9 12; 12 16]) / 2 = [6 8; 9 12]
```

不需要 W，也不需要通信：每个 rank 都有全部样本，自己就能算出整个 batch 的平均，结果正好是 dW 的第 1–2 列和第 3–4 列。

输入梯度：把 dx = dy · Wᵀ 按列分块展开：

```text
dx = (dy 的第 1–2 个分量) · W0ᵀ + (dy 的第 3–4 个分量) · W1ᵀ

rank 0：[1 2] · W0ᵀ = [5, 17]     ← 部分和（两个样本相同）
rank 1：[3 4] · W1ᵀ = [25, 53]    ← 部分和
all-reduce 求和：两个 rank 都得到 dx1 = dx2 = [5, 17] + [25, 53] = [30, 70]
```

- 每一项只用到一个 rank 自己的权重，所以不需要完整的 W。
- 但每个 rank 算出的只是部分和，相加才是 dx。用 all-reduce，是因为前一层在每个 rank 上都需要完整的 dx。

**第 3 步：梯度同步，不需要。** 每个 rank 的权重梯度已经覆盖整个 batch，而且只对应自己那片权重。

**第 4 步：update，不通信。** rank 0 用 `[2 4; 3 6]` 更新 W0，rank 1 用 `[6 8; 9 12]` 更新 W1。

**小结**：TP 把每一层的计算按输出特征分给各个 rank，权重从不移动。代价是每一层都要交换激活（forward）和激活的梯度（backward）。

### 1.5 结果核对

| 方案 | rank 0 最终的权重梯度 | rank 1 最终的权重梯度 |
|---|---|---|
| 单机 | dW = [2 4 6 8; 3 6 9 12] | — |
| DP | [2 4 6 8; 3 6 9 12]（完整） | [2 4 6 8; 3 6 9 12]（完整） |
| FSDP | [2 4; 3 6]（dW 的第 1–2 列） | [6 8; 9 12]（dW 的第 3–4 列） |
| TP | [2 4; 3 6]（dW 的第 1–2 列） | [6 8; 9 12]（dW 的第 3–4 列） |

三种方案得到的梯度都和单机一致。DP 每个 rank 有完整的一份；FSDP 和 TP 每个 rank 只有自己那片，正好用来更新自己存的那片权重。

## 第二部分：对比与扩展

### 2.1 核心：数据和权重必须在同一个 rank 上

每一次 y = x · W 都要求 x 和 W 在同一个 rank 上。三种方案的区别，就在于怎么满足这个要求：

- **DP**：每个 rank 都存一份完整的 W，数据和权重天然在一起，计算时什么都不用搬，代价是显存。
- **FSDP**：数据留在原地，用之前把权重搬过来（all-gather），用完就丢。
- **TP**：权重留在原地，让每个 rank 都有全部数据，算完交换激活。

还有一点很关键：**一个 rank 需要什么，取决于它负责算什么，而不是它存了什么。** 例子里 FSDP 和 TP 的存法完全相同，但是：

- FSDP 的 rank 负责“自己样本的全部输出特征”，需要 W 的全部列，所以必须 gather；
- TP 的 rank 负责“全部样本的部分输出特征”，只需要自己那几列，所以不用 gather，但要交换激活。

### 2.2 各自的代价

- **DP**：最简单。每步只同步一次梯度，而且可以在 backward 进行时同步，把通信藏在计算后面。问题在显存：每个 rank 都要放下完整的权重、梯度和优化器状态，模型一大就放不下。只切分优化器状态，是介于 DP 和 FSDP 之间的做法（作业第 6 章）。
- **FSDP**：计算和 DP 一样，模型状态的显存降到约 1/N。代价是通信变多：除了梯度，每一层的权重在 forward 和 backward 前都要 all-gather。可以提前发起后面层的 all-gather（预取），让它和当前层的计算重叠。从另一个角度看，DP 的 all-reduce 等于 reduce-scatter 加 all-gather；FSDP 对梯度只做 reduce-scatter，all-gather 则挪到了下一次使用权重之前。很小的层（比如 norm）不值得切分。
- **TP**：每一层的计算和权重都被切开，每个 rank 的计算量和权重存储都降到约 1/N。代价是每一层都要交换激活和激活的梯度，而且下一步计算必须等通信完成。通信非常频繁，所以 TP 通常放在同一台机器内、带宽很高的 GPU 之间。另外，每个 rank 都要处理全部样本的激活。

哪种方案的通信量更大，取决于模型和 batch 的具体尺寸，讲义第 8 章会定量比较。

### 2.3 扩展：PP（流水线并行）

PP 按层切。以 4 层的网络、2 个 rank 为例：

```text
rank 0：第 1、2 层（每一层都完整，不切）
rank 1：第 3、4 层
```

- **数据**：不在 rank 之间切分，所有样本都要依次经过 rank 0 和 rank 1。
- **forward**：rank 0 算完第 1、2 层，把激活 send 给 rank 1；rank 1 接收后算第 3、4 层，得到 loss。
- **backward**：方向相反。rank 1 算完第 4、3 层的反向，把激活的梯度 send 回 rank 0；rank 0 再算第 2、1 层的反向。
- **梯度同步**：不需要。每一层只在一个 rank 上，它的梯度也只在那个 rank 上算。
- **通信**：只在切口处传激活和激活的梯度，而且只在相邻的两个 rank 之间点对点地 send / recv，不是集合操作。
- **显存**：每个 rank 只存自己那几层的权重、梯度、优化器状态和激活。

PP 的主要问题是**气泡（bubble）**：rank 1 要等 rank 0 算完才能开始，backward 时 rank 0 又要等 rank 1，总有 rank 在空等。缓解的办法是把 batch 切成多个 micro-batch，让不同的 rank 同时处理不同的 micro-batch：

```text
forward：
rank 0：[mb1][mb2][mb3][mb4]
rank 1：     [mb1][mb2][mb3][mb4]
```

rank 1 处理 mb1 时，rank 0 已经在处理 mb2。切 micro-batch 只是在时间上错开，每个 micro-batch 仍要经过所有 rank，所以这不是数据并行。

### 2.4 四种策略一览

| | DP | FSDP | TP | PP |
|---|---|---|---|---|
| 切什么 | 数据 | 数据，以及模型状态的存储 | 每一层的权重和计算 | 层 |
| 平时存的权重 | 完整一份 | 1/N | 每层的 1/N | 自己那几层 |
| 计算时用的权重 | 完整的 | 完整的（临时拼回） | 只用自己那片 | 自己那几层 |
| 每个 rank 负责算 | 自己样本的全部特征 | 自己样本的全部特征 | 全部样本的部分特征 | 全部样本经过自己那几层 |
| forward 通信 | 无 | all-gather 权重 | all-gather 激活 | send 激活给下一段 |
| backward 通信 | 无 | all-gather 权重 | all-reduce 激活的梯度 | send 激活的梯度给上一段 |
| 梯度同步 | all-reduce | reduce-scatter | 不需要 | 不需要 |
| 梯度、优化器状态 | 完整一份 | 1/N | 1/N | 自己那几层 |
| 什么从不移动 | 权重（已复制） | 数据和激活 | 权重 | 权重 |
| 主要代价 | 显存冗余 | 通信更多，需要预取来隐藏 | 每层都要等通信，需要高带宽 | 气泡 |

### 2.5 组合使用与补充

- **组合使用**：大模型训练通常把几种策略组合起来。TP 放在同一台机器内，因为它需要高带宽；DP 或 FSDP 跨机器；PP 把模型分成几段，放到不同的机器组上。“TP 不切数据”只是在同一个 TP 组内部：数据先在不同的组之间切开，同一个 TP 组里的 rank 共享同一份数据。
- **TP 的另一种切法：按行切（切输入维度）。** 每个 rank 存 W 的几行，并且只用输入中对应的那几个特征。例子里，rank 0 存第 1 行，只用 s1 的第 1 个特征：`1 × [1 2 3 4] = [1, 2, 3, 4]`；rank 1 存第 2 行，只用第 2 个特征：`2 × [5 6 7 8] = [10, 12, 14, 16]`。两者都是和 y1 同形状的部分和，all-reduce 求和后得到 `[11, 14, 17, 20]`。
- **多个 TP 层连在一起时**：按列切的层输出的是按特征切开的激活，正好可以直接作为下一个按行切的层的输入，中间的 all-gather 就省掉了。讲义 §8.4 的 FFN 就是这样配置的。

## 附：用到的通信操作

| 操作 | 每个 rank 的输入 → 输出 | 本文中用在哪 |
|---|---|---|
| broadcast | 一个 rank 的完整张量 → 所有 rank 都得到一份 | DP、FSDP 开始训练前同步初始权重 |
| all-reduce | 完整张量 → 所有 rank 求和后的完整张量 | DP 的梯度同步；TP 的输入梯度 |
| all-gather | 自己那一片 → 所有片拼成的完整张量 | FSDP 拼权重；TP 拼激活 |
| reduce-scatter | 完整张量 → 求和后属于自己的那一片 | FSDP 的梯度同步 |
| send / recv | 一个 rank 发送，相邻的另一个 rank 接收 | PP 在切口处传激活和激活的梯度 |
