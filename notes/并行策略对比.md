# 并行策略：DP、ZeRO-1/2、FSDP（ZeRO-3）、TP、PP、EP

训练时把工作分给多个 rank（每个 rank 通常是一张 GPU）。能切开的东西有三样：**数据**（样本）、**每一层的权重**、**层**。DP、ZeRO-1/2 和 FSDP 切数据（后两者还把模型状态的存储切开），TP 切每一层的权重，PP 切层。MoE 模型还有一种切法：EP 把不同的专家放到不同的 rank 上。

第一部分用一个很小的例子，把 DP、ZeRO-1/2、FSDP、TP 的每一步完整走一遍；第二部分对比它们，并扩展到 PP 和 EP。

记号：`[1 2 3 4; 5 6 7 8]` 表示一个两行的矩阵，分号分隔各行；xᵀ 表示 x 的转置；N 表示相应并行组内的 rank 数，组合并行时不一定等于总 GPU 数。

**本文的比较口径**：先比较各策略单独使用的情况，假设各 rank 的有效样本数相同、参数均匀切分，没有跨层共享参数，也没有梯度累积。把 backward 计算和梯度同步分开写是为了讲清步骤，实际通信可以分桶并与 backward 重叠。TP 示例采用单个按列切的线性层，前后接口复制；FSDP 采用 forward 后重新分片、backward 前再聚合的方案。

## 第一部分：用一个例子走完 DP、ZeRO、FSDP、TP

### 1.1 例子

```text
一个线性层：y = x · W

W = [1 2 3 4]      权重：2 个输入特征 → 4 个输出特征（2×4）
    [5 6 7 8]

两个样本：s1 = [1, 2]，s2 = [3, 4]（每个都是 1×2）
两个 rank：rank 0、rank 1
```

这一层位于网络中间：输入 x 来自前一层，输出 y 交给后一层。

**单机训练时的计算（作为标准答案）**

```text
forward：
  y1 = s1 · W = [11, 14, 17, 20]
  y2 = s2 · W = [23, 30, 37, 44]

backward：后一层传回每个样本输出的梯度 dy。为了好算，两个样本都取 dy = [1, 2, 3, 4]
  权重梯度：每个样本 G = xᵀ · dy，形状 2×4，和 W 相同
    G(s1) = [1; 2] · [1 2 3 4] = [1 2 3 4; 2 4 6 8]
    G(s2) = [3; 4] · [1 2 3 4] = [3 6 9 12; 4 8 12 16]
    batch 的 loss 是两个样本 loss 的平均，所以
    dW = (G(s1) + G(s2)) / 2 = [2 4 6 8; 3 6 9 12]
  输入梯度：每个样本 dx = dy · Wᵀ，形状 1×2，交给前一层继续反传
    dx1 = dx2 = [1 2 3 4] · Wᵀ = [30, 70]

update：带动量的 SGD，学习率 0.1。动量缓冲 b 就是优化器状态，第一步 b = dW
  b = [2 4 6 8; 3 6 9 12]
  新 W = W - 0.1 · b = [0.8 1.6 2.4 3.2; 4.7 5.4 6.1 6.8]
```

- **梯度的口径**：dy、dx 都是对单个样本自己的 loss 求的梯度，batch 平均的 1/2 只在合并权重梯度时乘一次。这和 DP 的实际做法一致：每个 rank 先对本地的 loss 求导，梯度同步时再除以 rank 数。若各 rank 的有效样本或 token 数不同，应按实际数量加权，不能直接平均各 rank 的局部均值。如果用 autograd 直接对 batch 平均的 loss 求导，1/2 会提前乘进 dy，dx 变成 [15, 35]，dW 不变。
- **优化器**：为了好算，用带动量的 SGD。之后每一步 b = 0.9 · b + 新的梯度，所以 b 必须一直存着，它就是各方案要决定怎么存的优化器状态。实际训练常用 Adam，它有 m、v 两份状态，道理相同。

下面几种方案都用 2 个 rank 完成这些计算，最终的权重梯度和更新后的权重都必须和这里一致。

### 1.2 DP：切数据，每个 rank 存一整份权重

**分工**：rank 0 处理 s1，rank 1 处理 s2。两个 rank 各存一份完整的 W，以及完整的梯度和优化器状态。

**第 0 步：开始训练前，broadcast 权重。** 把 rank 0 的 W 复制给 rank 1，保证两份 W 完全相同。这一步只做一次。

**第 1 步：forward，不通信。**

```text
rank 0：y1 = s1 · W = [11, 14, 17, 20]
rank 1：y2 = s2 · W = [23, 30, 37, 44]
```

每个 rank 都有完整的 W 和自己的样本，计算所需的东西都在本地。

**第 2 步：backward，不通信。**

```text
rank 0：G0 = G(s1) = [1 2 3 4; 2 4 6 8]，dx1 = [30, 70]
rank 1：G1 = G(s2) = [3 6 9 12; 4 8 12 16]，dx2 = [30, 70]
```

dx1 只属于 s1，只有 rank 0 上的前一层需要它，所以也不用传。

**第 3 步：梯度同步，all-reduce。**

```text
all-reduce 求和：两个 rank 都得到 G0 + G1 = [4 8 12 16; 6 12 18 24]
各自除以 2：    两个 rank 都得到 dW = [2 4 6 8; 3 6 9 12]
```

为什么要同步：G0 只反映 s1，G1 只反映 s2，整个 batch 的梯度需要把两者合起来。all-reduce 之后，两个 rank 的梯度完全相同。

**第 4 步：update，不通信。**

```text
rank 0、rank 1 各自：b = dW，新 W = W - 0.1 · b = [0.8 1.6 2.4 3.2; 4.7 5.4 6.1 6.8]
```

两个 rank 用相同的 dW 做相同的更新，W 始终保持一致。所以权重只需要在开始时广播一次，之后不用再传。

**小结**：DP 把计算平分给两个 rank，每步进行一轮梯度同步（可以包含多次分桶通信）。代价是每个 rank 都存完整的权重、梯度和优化器状态，N 个 rank 就有 N 份重复。

### 1.3 ZeRO-1、ZeRO-2：切数据，只切一部分模型状态

DP 的模型状态有 N 份重复（见 1.2 小结）。ZeRO（Zero Redundancy Optimizer）把重复的部分切开，每个 rank 只存 1/N。按切多少分三级（stage）：

- **ZeRO-1**：只切优化器状态
- **ZeRO-2**：再切梯度
- **ZeRO-3**：连权重也切，基本就是下一节（1.4）的 FSDP

三级都是数据并行：分工和 DP 一样，rank 0 处理 s1，rank 1 处理 s2，计算时都用完整的 W。区别只在每个 rank 平时存多少。

#### ZeRO-1：只切优化器状态

**分工**：两个 rank 都存完整的 W 和完整的梯度，只有优化器状态按列切开。**每个 rank 只负责更新自己那一半 W**，更新完再 **all-gather 拼回完整的新 W**（第 5 步）：

```text
rank 0 只存 W 第 1–2 列的动量缓冲 b，只负责更新第 1–2 列
rank 1 只存 W 第 3–4 列的动量缓冲 b，只负责更新第 3–4 列
```

**第 0 步：开始训练前，broadcast 权重。** 和 DP 一样，只做一次。

**第 1、2 步：forward、backward，不通信。** 和 DP 完全一样。backward 结束时，rank 0 有完整形状的 G0 = [1 2 3 4; 2 4 6 8]，rank 1 有 G1 = [3 6 9 12; 4 8 12 16]。

**第 3 步：梯度同步，reduce-scatter。**

```text
先逐元素求和：G0 + G1 = [4 8 12 16; 6 12 18 24]
再按列切开：  rank 0 拿第 1–2 列 [4 8; 6 12]，rank 1 拿第 3–4 列 [12 16; 18 24]
各自除以 2：  rank 0 得到 [2 4; 3 6]，rank 1 得到 [6 8; 9 12]
```

结果正好是 dW 的第 1–2 列和第 3–4 列。为什么不用 all-reduce：rank 0 只更新第 1–2 列，用不到另一半的平均梯度。

**第 4 步：update，不通信。**

```text
rank 0：b = [2 4; 3 6]，新的第 1–2 列 = [1 2; 5 6] - 0.1 · b = [0.8 1.6; 4.7 5.4]
rank 1：b = [6 8; 9 12]，新的第 3–4 列 = [3 4; 7 8] - 0.1 · b = [2.4 3.2; 6.1 6.8]
```

每个 rank 的 b 只有一半大小，这就是 ZeRO-1 省下的显存。这时 rank 0 的 W 只有第 1–2 列是新的，第 3–4 列还是旧的 [3 4; 7 8]；rank 1 正好反过来。

**第 5 步：参数同步，all-gather。**

```text
all-gather：rank 0 发出 [0.8 1.6; 4.7 5.4]，rank 1 发出 [2.4 3.2; 6.1 6.8]
两个 rank 都拼出新 W = [0.8 1.6 2.4 3.2; 4.7 5.4 6.1 6.8]，和单机结果一致
```

拼好的 W 一直留在每个 rank 上，下一步的 forward、backward 直接用，不用再通信。

#### ZeRO-2：再切梯度

步骤和 ZeRO-1 相同，区别只在完整形状的梯度留多久：

```text
ZeRO-1：这里用保留完整梯度缓冲区直到 update 结束的实现作比较
ZeRO-2：梯度按层或桶产生后做 reduce-scatter，通信完成且不再被使用后，只留自己那一片
```

单层的例子看不出差别，换成两层：第 1 层是例子里的 W（2×4），第 2 层是另一个 4×2 的权重 V（数值不重要，只看个数）。两层的完整梯度各 8 个数，切成两半各 4 个。backward 先算第 2 层，再算第 1 层，rank 0 手里的梯度这样变化：

| backward 进行到 | ZeRO-1 的 rank 0 | ZeRO-2 的 rank 0 |
|---|---|---|
| 算出 V 的梯度 | V 完整：8 个 | V 完整 8 个，reduce-scatter 后只留一半：4 个 |
| 算出 W 的梯度 | V、W 都完整：16 个 | V 一半加 W 完整：12 个，reduce-scatter 后剩 8 个 |
| backward 结束到 update | 16 个（reduce-scatter 之后也留着） | 8 个 |

这里的 ZeRO-1 示例保留整个模型的完整梯度；ZeRO-2 的持久梯度只存 1/N。上表忽略额外通信缓冲区，且假设每层通信结束后再释放完整梯度；实际峰值还取决于桶大小和同时在途的通信数。ZeRO-1 的定义是只切优化器状态，并不强制完整梯度必须保留到 update 结束。ZeRO-2 在 backward 中及时归约并释放完整梯度，才能避免把整个模型的完整梯度同时攒在显存里。

#### 小结

ZeRO 论文把这几种做法排成一条线，每升一级多切一样东西：

| | 参数 | 梯度 | 优化器状态 |
|---|---|---|---|
| DP | 全部 | 全部 | 全部 |
| ZeRO-1（作业第 6 章是它的简化版） | 全部 | 全部 | 1/N |
| ZeRO-2 | 全部 | 1/N | 1/N |
| ZeRO-3 ≈ FSDP（作业第 7 章） | 1/N | 1/N | 1/N |

- **显存**：以 FP32 训练、Adam 优化器为例，每个参数的模型状态占 16 字节（参数 4、梯度 4、m 和 v 共 8）。按每个参数算，每个 rank 要存的字节数：DP 16，ZeRO-1 8 + 8/N，ZeRO-2 4 + 12/N，ZeRO-3 16/N。例子里 N = 2，依次是 16、12、10、8。这只统计持久模型状态，不包含激活、临时完整权重、通信缓冲区、内存碎片或缓存；不是训练峰值显存。
- **通信**：ZeRO-1、ZeRO-2 和 DP 一样多（原因见 2.2）。ZeRO-3（下一节的 FSDP）每层权重在 forward 和 backward 前各要 all-gather 一次，加上梯度的 reduce-scatter 共三份，而 DP 是两份，所以在上述通信模式下约是 DP 的 1.5 倍。这里假设参数和梯度通信的每元素字节数相同、每步只有这两次权重聚合和一次梯度归约，并忽略启动延迟。若张量大小为 S 字节，按 ring 算法计每个 rank 的发送量，一次 all-gather 或 reduce-scatter 是 (N−1)/N · S，all-reduce 是其两倍。混合精度、梯度累积、重计算和保留完整权重都会改变比较，通信量之比也不等于耗时之比。

### 1.4 FSDP：切数据，也切权重的存储

**分工**：和 DP 一样，rank 0 处理 s1，rank 1 处理 s2。区别是权重也切开（即 1.3 里的 ZeRO-3）：平时每个 rank 只存 W 的一半，以及对应那一半的梯度和优化器状态：

```text
rank 0 存 W 的第 1–2 列：[1 2; 5 6]
rank 1 存 W 的第 3–4 列：[3 4; 7 8]
```

**第 0 步：开始训练前，broadcast 权重，再各自切出一半。** 先把 rank 0 的完整 W 广播出去，保证两个 rank 从同一个 W 切出自己那一半，之后完整的 W 就丢掉。

**第 1 步：forward，先 all-gather 权重。**

```text
all-gather：rank 0 发出 [1 2; 5 6]，rank 1 发出 [3 4; 7 8]，两个 rank 都拼出完整的 W
rank 0：y1 = s1 · W = [11, 14, 17, 20]
rank 1：y2 = s2 · W = [23, 30, 37, 44]
算完立刻丢掉完整的 W，只留自己那一半
```

**实现上的释放条件**：这里的“丢掉”是理想的完整权重生命周期。若 autograd 保存了完整权重或其视图，仅把参数的 `.data` 换回分片并不保证底层存储立即释放。应结合保存的张量和显存测量验证，不能由这份示意流程推断自写脚本一定达到相同峰值显存。

为什么要 gather：rank 0 要算出 s1 的全部 4 个输出特征（后一层需要完整的 y1），这要用到 W 的全部列。第 3–4 列在 rank 1 上，但 rank 1 没有 s1，帮不上忙，只能把权重搬到 rank 0。

**第 2 步：backward，再 all-gather 一次权重。**

```text
all-gather：两个 rank 再次拼出完整的 W（forward 之后已经丢掉了）
rank 0：G0 = G(s1) = [1 2 3 4; 2 4 6 8]，dx1 = [30, 70]
rank 1：G1 = G(s2) = [3 6 9 12; 4 8 12 16]，dx2 = [30, 70]
算完再丢掉完整的 W
```

- 需要完整 W 的是 dx：dx1 = dy · Wᵀ 要用到 W 的全部列。权重梯度 G = xᵀ · dy 只用到 x 和 dy，不需要 W。
- G0 的形状是完整的 2×4，但只包含 s1 的贡献，还不是整个 batch 的梯度。
- 和 DP 一样，dx1 留在 rank 0，不用传。

**第 3 步：梯度同步，reduce-scatter。** 和 ZeRO-1 的第 3 步一样，rank 0 得到 [2 4; 3 6]，rank 1 得到 [6 8; 9 12]。之后和 ZeRO-2 一样，完整形状的 G0、G1 可以丢掉。

**第 4 步：update，不通信。** 计算和 ZeRO-1 的第 4 步一样：rank 0 把自己存的第 1–2 列更新成 [0.8 1.6; 4.7 5.4]，rank 1 把第 3–4 列更新成 [2.4 3.2; 6.1 6.8]。和 ZeRO-1 不同，update 之后不做 all-gather：下一次 forward 用到这一层时才临时拼回，自然拿到更新后的权重。

**小结**：FSDP 中每个 rank 的计算和 DP 完全相同，区别只在存储：权重、梯度、优化器状态平时只存 1/N，用到某一层时才临时拼出完整的权重。代价是每层权重在 forward、backward 前各要 all-gather 一次，在 1.3 所列假设下，通信量约为 DP 的 1.5 倍。

### 1.5 TP：不切数据，每个 rank 只用自己那片权重计算

**分工**：两个 rank 都处理 s1 和 s2。权重的存法和 FSDP 一样：rank 0 存第 1–2 列 W0 = `[1 2; 5 6]`，rank 1 存第 3–4 列 W1 = `[3 4; 7 8]`。但 TP 计算时每个 rank 只用自己那片，**从不拼回完整的 W**。

这里假设这一层的前一层和后一层都在每个 rank 上完整运行，也就是每个 rank 都需要完整的输入和输出。

**第 0 步：开始训练前，各自从同一个 W 切出自己那片。** 和 FSDP 的第 0 步一样，之后完整的 W 不再出现。

**第 1 步：forward，算完再 all-gather 激活。**

```text
rank 0：[s1; s2] · W0 = [11 14; 23 30]  ← 两个样本的第 1–2 个输出特征
rank 1：[s1; s2] · W1 = [17 20; 37 44]  ← 两个样本的第 3–4 个输出特征
all-gather 激活：两个 rank 都得到 y1 = [11, 14, 17, 20]，y2 = [23, 30, 37, 44]
```

- 每个 rank 算出的就是最终值：y 的第 j 个特征只依赖 x 和 W 的第 j 列，所以 `[11, 14]` 就是 y1 前两个特征的最终结果，不需要再相加。
- 为什么要 all-gather：后一层需要每个样本的**全部 4 个特征**，而每个 rank 只算出了其中 2 个。
- 权重始终不动，搬的是激活。

**第 2 步：backward，权重梯度在本地算，输入梯度要 all-reduce。**

后一层在每个 rank 上都完整运行，所以两个 rank 拿到相同、完整的 dy：两个样本都是 `[1, 2, 3, 4]`。

权重梯度：rank 0 只负责 W0，只需要 dy 的第 1–2 个分量；rank 1 只需要第 3–4 个分量。

```text
rank 0：([1; 2] · [1 2] + [3; 4] · [1 2]) / 2 = ([1 2; 2 4] + [3 6; 4 8]) / 2 = [2 4; 3 6]
rank 1：([1; 2] · [3 4] + [3; 4] · [3 4]) / 2 = ([3 4; 6 8] + [9 12; 12 16]) / 2 = [6 8; 9 12]
```

不需要 W，也不需要通信：每个 rank 都有全部样本，自己就能算出整个 batch 的平均，结果正好是 dW 的第 1–2 列和第 3–4 列。

输入梯度：把 dx = dy · Wᵀ 按列分块展开：

```text
dx = (dy 的第 1–2 个分量) · W0ᵀ + (dy 的第 3–4 个分量) · W1ᵀ

rank 0：[1 2] · W0ᵀ = [5, 17]     ← 部分和（两个样本相同）
rank 1：[3 4] · W1ᵀ = [25, 53]    ← 部分和
all-reduce 求和：两个 rank 都得到 dx1 = dx2 = [5, 17] + [25, 53] = [30, 70]
```

- 每一项只用到一个 rank 自己的权重，所以不需要完整的 W。
- 但每个 rank 算出的只是部分和，相加才是 dx。用 all-reduce，是因为前一层在每个 rank 上都需要完整的 dx。

**第 3 步：梯度同步，不需要。** 每个 rank 的权重梯度已经覆盖整个 batch，而且只对应自己那片权重。

**第 4 步：update，不通信。** 计算和 ZeRO-1 的第 4 步一样：rank 0 的 W0 变成 [0.8 1.6; 4.7 5.4]，rank 1 的 W1 变成 [2.4 3.2; 6.1 6.8]。

**小结**：TP 把每一层的计算按输出特征分给各个 rank，权重从不移动。代价是每一层都要交换激活（forward）和激活的梯度（backward）。

### 1.6 结果核对

| 方案 | rank 0 最终的权重梯度 | rank 1 最终的权重梯度 | update 后每个 rank 存的 W |
|---|---|---|---|
| 单机 | dW = [2 4 6 8; 3 6 9 12] | — | 新 W = [0.8 1.6 2.4 3.2; 4.7 5.4 6.1 6.8] |
| DP | [2 4 6 8; 3 6 9 12]（完整） | [2 4 6 8; 3 6 9 12]（完整） | 都是完整的新 W |
| ZeRO-1/2 | [2 4; 3 6]（dW 的第 1–2 列） | [6 8; 9 12]（dW 的第 3–4 列） | 都是完整的新 W（all-gather 拼回） |
| FSDP | [2 4; 3 6]（dW 的第 1–2 列） | [6 8; 9 12]（dW 的第 3–4 列） | 只存一半：rank 0 [0.8 1.6; 4.7 5.4]，rank 1 [2.4 3.2; 6.1 6.8] |
| TP | [2 4; 3 6]（dW 的第 1–2 列） | [6 8; 9 12]（dW 的第 3–4 列） | 同 FSDP |

各方案的梯度和更新后的权重都和单机一致。DP 每个 rank 有完整的一份梯度；ZeRO、FSDP 和 TP 每个 rank 只有自己那片，正好用来更新自己负责的那片权重。更新之后，DP 和 ZeRO 的每个 rank 都有完整的新 W，FSDP 和 TP 的每个 rank 只存一半。

## 第二部分：对比与扩展

### 2.1 核心：数据和权重必须在同一个 rank 上

每一次 y = x · W 都要求 x 和 W 在同一个 rank 上。下面先对比 DP、FSDP、TP 怎么满足这个要求；ZeRO-1/2 在计算时与 DP 相同：

- **DP**：每个 rank 都存一份完整的 W，数据和权重天然在一起，计算时什么都不用搬，代价是显存。
- **FSDP**：数据留在原地，用之前把权重搬过来（all-gather），用完就丢。
- **TP**：权重留在原地，让每个 rank 都有全部数据，算完交换激活。

还有一点很关键：**一个 rank 需要什么，取决于它负责算什么，而不是它存了什么。** 例子里 FSDP 和 TP 的存法完全相同，但是：

- FSDP 的 rank 负责“自己样本的全部输出特征”，需要 W 的全部列，所以必须 gather；
- TP 的 rank 负责“全部样本的部分输出特征”，只需要自己那几列，所以不用 gather，但要交换激活。

### 2.2 各自的代价

- **DP**：最简单。每步进行一轮梯度同步（可以包含多次分桶通信），而且可以在 backward 进行时同步，把通信藏在计算后面。问题在显存：每个 rank 都要放下完整的权重、梯度和优化器状态，模型一大就放不下。
- **ZeRO-1/2**：通信量和 DP 一样，却去掉了优化器状态（ZeRO-2 还有梯度）的冗余。原因是 DP 的 all-reduce 本来就等于 reduce-scatter 加 all-gather：DP 把两半连着做，都用在梯度上；ZeRO 在两半之间插进 update，后一半的 all-gather 改成同步新权重。代价是权重仍然每个 rank 存一份，模型再大就放不下，这时才需要 FSDP。
- **FSDP**：计算和 DP 一样，模型状态的显存降到约 1/N。代价是通信变多：权重平时不完整，all-gather 只能搬到每次使用权重之前，forward 和 backward 各做一次。可以提前发起后面层的 all-gather（预取），让它和当前层的计算重叠。很小的层（比如 norm）不值得切分。
- **TP**：每一层的计算和权重都被切开，每个 rank 的计算量和权重存储都降到约 1/N。代价是每一层都要交换激活和激活的梯度，而且下一步计算必须等通信完成。通信非常频繁，所以 TP 通常放在同一台机器内、带宽很高的 GPU 之间。另外，每个 rank 都要处理全部样本的激活。

哪种方案的通信量更大，取决于模型和 batch 的具体尺寸，讲义第 8 章会定量比较。

### 2.3 扩展：PP（流水线并行）

PP 按层切。以 4 层的网络、2 个 rank 为例：

```text
rank 0：第 1、2 层（每一层都完整，不切）
rank 1：第 3、4 层
```

**分工**：数据不在 rank 之间切分，所有样本都要依次经过 rank 0 和 rank 1。每个 rank 只存自己那几层的权重、梯度、优化器状态和激活。

**第 0 步：开始训练前，不通信。** 每一层只在一个 rank 上，没有副本需要对齐。

**第 1 步：forward，在切口处 send 激活。** rank 0 算完第 1、2 层，把第 2 层的输出 send 给 rank 1；rank 1 接收后算第 3、4 层，得到 loss。

**第 2 步：backward，在切口处 send 激活的梯度。** 方向相反：rank 1 算完第 4、3 层的反向，把 loss 对第 2 层输出的梯度 send 回 rank 0；rank 0 再算第 2、1 层的反向。

**第 3 步：梯度同步，不需要。** 每一层只在一个 rank 上，它的梯度也只在那个 rank 上算。

**第 4 步：update，不通信。** 每个 rank 只更新自己那几层。

PP 的通信只在切口处传激活和激活的梯度，而且只在相邻的两个 rank 之间点对点地 send / recv，不是集合操作。所以对网络带宽要求较低，属于通信开销小（communication efficient）的策略。相比之下，TP 对带宽的要求高得多（communication hungry）。

PP 的主要问题是**气泡（bubble）**：rank 1 要等 rank 0 算完才能开始，backward 时 rank 0 又要等 rank 1，总有 rank 在空等。缓解的办法是把 batch 切成多个 micro-batch，让不同的 rank 同时处理不同的 micro-batch：

```text
forward：
rank 0：[mb1][mb2][mb3][mb4]
rank 1：     [mb1][mb2][mb3][mb4]
```

rank 1 处理 mb1 时，rank 0 已经在处理 mb2。切 micro-batch 只是在时间上错开，每个 micro-batch 仍要经过所有 rank，所以这不是数据并行。

### 2.4 扩展：EP（专家并行）

EP 只用于 MoE（Mixture of Experts）模型。MLP（也叫 FFN）是 Transformer block 里和 attention 并列的子层，对每个 token 单独做 d_model → d_ff → d_model 的变换。常见 MoE 把一层 MLP 换成多个“专家”（每个专家是一个 MLP，大小取决于模型设计），再加一个 router：router 给每个 token 选出 top-k 个专家，只有这几个专家参与计算，结果按 router 给的权重加起来。EP 的思路是**不切矩阵，而是把不同的专家放到不同的 rank 上，让 token 去找专家**。和 PP、TP 一样，EP 切的是参数，传的是激活。

以 2 个专家、2 个 rank、每个 token 只选 1 个专家为例。为了好算，每个专家只是一个 2×2 的线性层，并省略 router 给的权重：

```text
专家 1：y = x · A，A = [1 0; 0 2]
专家 2：y = x · B，B = [0 1; 1 0]

rank 0 的 token：t1 = [1, 2]，t2 = [3, 4]
rank 1 的 token：t3 = [5, 6]，t4 = [7, 8]
```

**分工**：数据和 DP 一样按样本切开。attention、router 等非专家参数，每个 rank 都存完整的一份；专家每个 rank 只存自己的：rank 0 存专家 1，rank 1 存专家 2。

**第 0 步：开始训练前，broadcast 非专家参数。** 每个专家只在一个 rank 上，不需要对齐。

**第 1 步：forward，先 all-to-all 发出 token，算完再 all-to-all 收回结果。**

```text
router 选专家（不通信）：t1 → 专家 2，t2 → 专家 1，t3 → 专家 1，t4 → 专家 2
dispatch（all-to-all）：rank 0 把 t1 发给 rank 1，rank 1 把 t3 发给 rank 0
  → rank 0 有 t2、t3，rank 1 有 t1、t4
rank 0 算专家 1：t2 · A = [3, 8]，t3 · A = [5, 12]
rank 1 算专家 2：t1 · B = [2, 1]，t4 · B = [8, 7]
combine（all-to-all）：rank 0 把 [5, 12] 发回 rank 1，rank 1 把 [2, 1] 发回 rank 0
  → rank 0 得到 y1 = [2, 1]、y2 = [3, 8]，rank 1 得到 y3 = [5, 12]、y4 = [8, 7]
```

结果和单机逐个 token 计算相同。每个 token 只发往它选中的专家所在的 rank，没被选中的专家完全不参与。

**第 2 步：backward，反方向再做两次 all-to-all。** 先把输出的梯度发到专家所在的 rank，算完专家的反向，再把输入的梯度发回 token 原来的 rank。

**第 3 步：梯度同步，专家不需要。** 在本例每个专家只有一份的前提下，它已收集所有来源 rank 中路由到自己的 token 的梯度，未选中它的 token 对它贡献为零，因此无需再对专家参数做副本间归约。非专家参数每个 rank 都有一份，和 DP 一样做 all-reduce。所有梯度仍须使用统一的全局 loss 归一化；不能各专家按收到的 token 数各自取平均，否则会改变训练目标。

**第 4 步：update，不通信。** 每个 rank 更新自己的专家，以及自己那份非专家参数。

**为什么不用 TP 切专家**：EP 和 TP 都能把 MLP 的权重分到多个 rank 上，也都要传激活、需要高带宽。但 TP 会把每个专家的矩阵再切开，每个 token 都要在对应 TP 组的所有 rank 上各算一片，再合并结果；专家本来就小，切碎后矩阵乘法太小，GPU 用不满。EP 让每个专家保持完整，每个 token 只发往它需要的 rank。用 2.1 的说法：EP 让权重（专家）留在原地，把数据（token）送过去。

**使用场景和注意事项**：

- **在本文讨论的常见 MoE Transformer 中，EP 用于专家 MLP 层。** 普通 attention 没有这些专家，不能直接套用这种 EP；它可以结合 TP、CP、DP、PP 等策略（见 2.6），并非只能用 TP。所以同一个 MoE 模型里，attention 适合大 TP，MoE 层适合小 TP、大 EP。Megatron 允许两种层分开配置：attention 用 TP、CP、DP，MoE 层用 ETP、EP、EDP（ETP、EDP 是专门给专家层用的 TP 和 DP）。
- **传统分组下，EP 可以划分 DP 使用的同一批 rank。** 本例中 EP 组是 DP 组的子组，所以 EP ≤ DP；一个专家在多个组中有副本时，这些副本之间仍要同步梯度。但这不是普遍上限：Megatron 的 MoE Parallel Folding 可以分别配置 attention 的 TP/CP/DP 和专家层的 ETP/EP/EDP，使 EP 超过 attention 的 DP 度数。参见 [Megatron MoE 文档](https://docs.nvidia.com/megatron-core/developer-guide/latest/user-guide/features/moe.html#moe-parallel-folding)。
- **代价在 all-to-all。** 每个 rank 都要和所有 rank 交换数据，最适合任意两点直连的网络，比如一台 GPU 机器内部；TPU 的环面网格更适合 TP 这种规则的通信。另外，每个专家要分到足够多的 token 才能把矩阵乘法跑满；router 分配不均时，热门专家所在的 rank 会拖慢所有 rank。
- **规模。** 经验法则是 TP、EP 放在一台机器之内，PP 跨机器，剩下的 GPU 用 DP。实际中 TP 一般不超过 8，EP 却可以开得很大（但难做好）：DeepSeek-V3 用 64 路 EP，跨 8 个节点，再加 16 段 PP 和 ZeRO-1，并让 all-to-all 和计算重叠；lecture_08 p.69 引用的 Megatron Mixtral 8x22B 配置为 TP 4、PP 4、CP 1、EP 8，这是一个配置示例，不是模型固定属性。DeepSeek-V3 的配置见其[技术报告 §3.2](https://arxiv.org/html/2412.19437v2#S3.SS2)。

### 2.5 各策略一览

下表沿用本文单独使用各策略的简化假设；TP 列描述 1.5 的按列切示例，EP 列假设每个专家没有副本。forward/backward 行不重复列出单独的“梯度同步”；实际执行时它们可以重叠。

| | DP | ZeRO-1/2 | FSDP | TP | PP | EP |
|---|---|---|---|---|---|---|
| 切什么 | 数据 | 数据，以及优化器状态（ZeRO-2 加梯度）的存储 | 数据，以及模型状态的存储 | 每一层的权重和计算 | 层 | MoE 层的专家 |
| 平时存的权重 | 完整一份 | 完整一份 | 1/N | 每层的 1/N | 自己那几层 | 非专家部分完整一份；专家只存自己的 |
| 计算时用的权重 | 完整的 | 完整的 | 完整的（临时拼回） | 只用自己那片 | 自己那几层 | 非专家用完整的，专家只用自己的 |
| 每个 rank 负责算 | 自己样本的全部特征 | 自己样本的全部特征 | 自己样本的全部特征 | 全部样本的部分特征 | 全部样本经过自己那几层 | 自己的样本；MoE 层里是发给自己专家的 token |
| forward 通信 | 无 | 无 | all-gather 权重 | all-gather 激活 | send 激活给下一段 | all-to-all 发出 token，再 all-to-all 收回结果 |
| backward 通信 | 无 | 无 | all-gather 权重 | all-reduce 激活的梯度 | send 激活的梯度给上一段 | 反方向两次 all-to-all |
| 梯度同步 | all-reduce | reduce-scatter | reduce-scatter | 不需要 | 不需要 | 专家不需要；非专家 all-reduce |
| update 之后 | 无 | all-gather 拼回更新后的完整权重 | 无（下次用到时再拼） | 无 | 无 | 无 |
| 梯度、优化器状态 | 完整一份 | 优化器状态 1/N；梯度 ZeRO-1 完整、ZeRO-2 1/N | 1/N | 1/N | 自己那几层 | 专家部分 1/N；非专家完整一份 |
| 什么从不移动 | 权重（已复制） | 数据和激活 | 数据和激活 | 权重 | 权重 | 专家权重 |
| 主要代价 | 显存冗余 | 权重仍是完整一份，只省一部分显存 | 通信更多，需要预取来隐藏 | 每层都要等通信，需要高带宽 | 气泡 | all-to-all 通信，专家负载不均 |

### 2.6 组合使用与补充

- **组合使用**：大模型训练通常把几种策略组合起来。TP 放在同一台机器内，因为它需要高带宽，MoE 模型的 EP 也优先利用高速互连，但可以跨机器扩展（见 2.4）；DP 或 FSDP 跨机器；PP 把模型分成几段，放到不同的机器组上。“TP 不切数据”只是在同一个 TP 组内部：数据先在不同的组之间切开，同一个 TP 组里的 rank 共享同一份数据。
- **TP 的另一种切法：按行切（切输入维度）。** 每个 rank 存 W 的几行，并且只用输入中对应的那几个特征。例子里，rank 0 存第 1 行，只用 s1 的第 1 个特征：`1 × [1 2 3 4] = [1, 2, 3, 4]`；rank 1 存第 2 行，只用第 2 个特征：`2 × [5 6 7 8] = [10, 12, 14, 16]`。两者都是和 y1 同形状的部分和，all-reduce 求和后得到 `[11, 14, 17, 20]`。
- **多个 TP 层连在一起时**：按列切的层输出的是按特征切开的激活，正好可以直接作为下一个按行切的层的输入，中间的 all-gather 就省掉了。讲义 §8.4 的 FFN 就是这样配置的。
- **推广到 attention**：前面的例子都是线性层，attention 里的 W_Q、W_K、W_V、W_O 也是线性层，照前面的方法处理；多出来的是 token 之间的交互（q·kᵀ、softmax、乘 v）。这一步没有权重，却把同一条序列里的所有 token 绑在了一起，所以要注意三点：

1. **DP、ZeRO、FSDP、PP 原样适用，但数据要按整条序列切。** MLP 里每个 token 独立计算，把一条序列拆到不同 rank 上也没问题；attention 里每个 token 都要用到同一条序列中其他 token 的 k、v，因此在没有 CP 等跨序列通信机制时，每个数据并行副本应处理完整序列。因果 attention 只依赖允许的前缀，滑动窗口 attention 只依赖窗口；并非所有 attention 都访问序列中的所有 token。
2. **标准多头 attention 的 TP 通常按完整 head 切。** W_Q、W_K、W_V 按列切，每个 rank 分到几个完整的 head；W_O 按行切，最后 all-reduce，和上一条 FFN 的“先按列、再按行”相同。各个 head 互不依赖，每个 rank 在本地就能算完自己的 head。如果切到 head 内部，q·k 的点积会被拆成部分和，softmax 之前要多一次 all-reduce。这种均匀切法要求 query head 数能被 TP 组大小整除；GQA/MQA 的 KV head 数不同，可能需要复制 KV head 或采用其他布局，不能把该整除条件直接套到所有 head 上。
3. **序列太长时，要切序列这一维。** 上面的策略都不切序列，而 attention 的激活随序列长度增长。一条序列长到一张卡放不下时，就要把它切到多个 rank 上（context parallel）：MLP 部分照样各算各的；ring attention 是一种做法：前向让 k、v 分块沿环传递，每个 rank 边收边用 online softmax 累加，和 FlashAttention 分块计算用的是同一个技巧；反向还需要相应的梯度通信。Context parallel 也可使用其他通信方式，并不等同于 ring attention。

## 附：用到的通信操作

| 操作 | 每个 rank 的输入 → 输出 | 本文中用在哪 |
|---|---|---|
| broadcast | 一个 rank 的完整张量 → 所有 rank 都得到一份 | 除 PP 外，各方案开始训练前同步初始权重 |
| all-reduce | 完整张量 → 所有 rank 求和后的完整张量 | DP（以及 EP 的非专家参数）的梯度同步；TP 的输入梯度；按行切的 TP（FFN 第二层、attention 的 W_O）的输出 |
| all-gather | 自己那一片 → 所有片拼成的完整张量 | ZeRO-1/2 在 update 后拼回新权重；FSDP 计算前拼权重；TP 拼激活 |
| reduce-scatter | 完整张量 → 求和后属于自己的那一片 | ZeRO-1/2、FSDP 的梯度同步 |
| all-to-all | 给每个 rank 各发一份不同的数据 → 收到每个 rank 发给自己的那份 | EP 把 token 发到专家所在的 rank，再把结果发回来 |
| send / recv | 一个 rank 发送，相邻的另一个 rank 接收 | PP 在切口处传激活和激活的梯度 |
